Explain the difference between TCP and UDP
ChatGPT said:

TCP (Transmission Control Protocol) and UDP (User Datagram Protocol) are both transport layer protocols, but they differ in several key ways:

TCP is connection-oriented. It establishes a reliable connection through a three-way handshake before data transfer begins. It guarantees delivery, ordering, and error-checking of packets.

UDP is connectionless. It sends data without establishing a connection first. There is no guarantee of delivery, ordering, or duplicate protection, making it faster but less reliable.

You said:
When would I choose UDP over TCP?
ChatGPT said:

UDP is preferred when speed matters more than reliability:

  • Real-time gaming — low latency is critical; a dropped packet is better than a delayed one
  • Video/audio streaming — minor data loss is acceptable over buffering
  • DNS lookups — small, single request-response exchanges
  • IoT sensors — frequent small updates where occasional loss is fine
You said:
How does TCP handle packet loss?
ChatGPT said:

TCP uses several mechanisms to handle packet loss:

1. Acknowledgments (ACKs): The receiver sends an ACK for each segment received. If the sender doesn't receive an ACK within a timeout period, it assumes the packet was lost.

2. Retransmission: Lost packets are retransmitted. TCP uses both timeout-based retransmission and fast retransmit (triggered by three duplicate ACKs).

3. Sliding window: TCP dynamically adjusts the window size to control flow and avoid congestion that leads to packet loss.
