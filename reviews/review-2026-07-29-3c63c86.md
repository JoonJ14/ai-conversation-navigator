## Why this round exists

v12.1 wrote a new persistence path — one that **rewrites stored user data on sight**, keyed to
evidence rather than to an identifier. A wrong binding there is not a failed jump; it is a
bookmark that permanently points at the wrong message and reports success. The whole review was
aimed at the refusal paths rather than the happy path.

## The two that matter most

**Rule C's reverse probe had no floor on the preview.** The needle is `want.substring(0, 40)` —
40 characters only when the preview *has* 40. A 14-character preview degraded the check to an
unbounded substring test, found incidental overlap, passed the uniqueness gate on that single
hit, and bound permanently. Three lenses reproduced it independently. The comment directly above
it asserted the opposite: *"uniqueness is the gate that makes 40 chars safe."* **Comment-vs-code
disagreement was the tell**, as it has been repeatedly in this codebase.

**Inference committed before proof and destroyed it.** `_bmCommitLegacyUpgrade` overwrote
`contentHash` — the one proof-grade artifact a legacy record carries — with the uuid. The text
rules ran first, so a wrong guess became permanent *and* unverifiable: the channel that could
have caught it had its input deleted by the channel that made the mistake. Now the hash is
preserved as `legacyHash`, records carry `boundBy: proof|inference`, proof runs first, and proof
may **correct** an inference binding. Recorded as **DEC-035**.

**Two things this cycle taught that the 24-round one did not:**

1. **Freezing the implementation is what shortens the loop** — not the backend. PR #58 ran 24
   rounds with code landing mid-loop (19 pre-existing / 23 cycle-introduced). PR #59 ran 7 with
   the implementation frozen going in. Same bot, same repo.
2. **Trigger a review on documentation-only pushes.** Round 5 ran on a docs commit and returned a
   real code finding four earlier rounds against the same file had missed. Codex re-reads the
   whole diff, so a doc push is a free second look. Stop once a round is clean *and* the code
   underneath has not changed.

## Honest limits of this round

- **Summary, Tools and Export still have zero test execution** (mutation-proven, unchanged from
  the previous round). Nothing in v12.1 improved that; it remains the highest-value item next.
- **Two assertions deliberately not written**, both recorded in the fixture rather than shipped
  green: "a harvest-bound record renders an ACTIVE flag" and "the click path records an
  exact-hash match as proof". In both cases the row is not reliably mounted (or the harvest
  proves the record first), so every assertion available passes by finding nothing — the exact
  shape DEC-032 exists to prevent.
- **Rule C's payload shape is n=1.** Probe E in `DOM-REFERENCE.md` states the context; the
  diagnostic's `summaries=` count is the regression signal.
- **A review lens wrote `tests/_review_probe.js` into the repo** despite instructions to work in
  a scratch directory. Deleted, tracked files verified intact. Standing rule reinforced: stage
  with explicit paths, never `git add -A`, while agents are running.
