### CRITICAL — S5 proved export→export reuse, not panel→export (test-integrity lens, mutation-proven)

By S5's position in the block, the last cache writer was E3's export (S4's switch had
re-minted the stamp, so E3 recomputed). A mutant clearing `_sumComputeCache` at the end
of the genBtn handler — a build where the exact user scenario v12.4 exists for
(panel generate → export) still double-computes — stayed **green** across the whole
suite. The lens also proved the fix: reordering S5's legs (regenerate first, then
export) turns that mutant red while real code stays green.
**Fixed:** S5 reordered — regenerate leg first; the reused cache is now the panel's
computation. Leg order documented as load-bearing in the fixture comment + TESTING.md.

### WARN — the cache KEY had no killing mutation (interfaces + test-integrity, mutation-proven)

`if (_sumComputeCache) return _sumComputeCache.data;` (all three validity conditions
dropped) left the suite green — E3 silently exported a summary from a dead index
generation; the shim serves identical payloads per uuid so no content assertion can
see it. **Fixed:** E3 now captures the computes delta across its export and asserts
exactly +1 ("EXPORT summary recomputes when the index generation has moved"). Post-fix
nuance (see verification below): the retention fix made the invalidate release a second,
redundant defense for the cross-conversation case, so the gate's named killing mutation
is the JOINT failure (bare key + release removed) — measured red exactly there. Title
added to FIXTURE PRESENCE (11 declared).

### WARN — qLen false-HIT: count-membership swap under a frozen stamp (lifecycle lens; skeptic CONFIRMED-WITH-CORRECTIONS, worse than reported)

The provisional set is rebuilt each scan from MOUNTED rows, so `_questions.length` can
return to a previous value with different membership (Q149's row evicts Q148's from the
~3-row window). The skeptic proved the stamp freeze is not a race: one 429 on a
background refresh puts the session in retained-degrade (`ready` restored, stamp
frozen, refetch gate 1–30 min) — the collision is a steady state there. The skeptic
also rejected my blunter fix (refuse-on-any-provisional: disables the cache for the
most common flow, send→generate→export) in favor of **provisional-set signature by
content** (`_sumProvSig`), which replaces qLen outright — the index half of
`_questions` is immutable per stamp (assigned only at `ciBuildIndex`'s commit point).
**Fixed:** cache key is now `{stamp, provSig}`.

### WARN — cache retention (all five lenses)

`_sumComputeCache` was never released: full conversation text + compute-time DOM nodes
survived `ciInvalidate()` — the function whose stated job is releasing exactly that
class of payload — and on 13 non-indexed platforms (and degraded sessions) the entry
was written but structurally unreadable: pure retention. **Fixed:** `ciInvalidate()`
nulls the cache; the write is skipped entirely when the stamp is null.

### WARN — S5 lacked the settle guard E1/E3 both carry (4 of 5 lenses)

An index reload inside the block re-mints the stamp; the cache then CORRECTLY refuses;
the "no recompute" gate reds on correct code — a cross-OS flake shaped exactly like the
DEC-025/webkit-macos class, in the one assertion that measures the absence of work.
**Fixed:** both S5 legs are preceded by the E3-style `__convFetches` settle wait.

### WARN — the live-run procedure would halt the owner against the fix build (correctness lens)

`probes/README.md` step 4 (the DEC-027 identity guard) demanded `over ACN v12.3` and
step 5 promised a run#3 the cache-hit path removes — an owner following it literally
stops at step 4 on the only build that can confirm the fix, and reads a healthy cache
hit as a failed measurement. **Fixed:** procedure is now version-explicit and describes
both build generations' expected outputs (run#3 vs `export cache: … HIT` + no run#3).

### WARN — mount-window snapshot in entities/inventory (correctness + lifecycle; skeptic: disposition SOUND with amendments)

The key cannot see the mounted-row set; entities (mount-only by construction) and
inventory (per-message DOM-vs-text branch; guaranteed to disagree on tool/artifact
answers) freeze at generate time on a cache hit. The skeptic bounded it (≤7% of
messages affected; entities describe only the ~3-5 mounted turns in EITHER build),
established that v12.4 is strictly better on the one user-visible axis (the exported
inventory counts now match the open panel exactly — same object — where v12.3 could
silently contradict it), and rejected keying on mount state (forfeits the cache per
scroll/jump; "recompute always" IS v12.3). **Disposition:** accepted + documented
(code comment, TESTING.md, TROUBLESHOOTING scope annotation); follow-up recorded to
thread the index's existing `toolBlocks` extraction into the unmounted inventory
branch (a pre-existing v12.0 extraction gap the cache freezes rather than creates).
The skeptic also flagged that the "byte-identical export" verification structurally
could not see this divergence (text-branch-only harness, no scroll between generate
and export) — the claim is now scope-annotated in TROUBLESHOOTING/TESTING rather than
left reading as a general equivalence proof.
