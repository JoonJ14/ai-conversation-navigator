## The live diagnosis — reproduced, not confirmed

**Not the estimator.** `ciDeriveRowOffset()` aligns `data-index` to the conversation path
by matching **rendered DOM text** against the API's **raw markdown**. Those need not
normalise to the same key — a code span, bold, a list, a link — and ~10% of human turns
carry no API text at all. When no mounted user row matches, it returns `null` and the loop
enters a blind-probe branch that scrolls to 1/9, 2/9 … 8/9 of the document: 8 moves at
~1.05 s each, viewport dragged across the whole conversation, then the honest-failure
toast.

Reproduced by a new platform entry, `Claude (virtualized, markdown API text)`:

```
EXIT=no-offset-after-probes iterations=8
18 feed mutations          (owner measured ~20 live)
```

Fits every reported fact: the ~12.5 s, the visible blinking, the non-determinism (it
depends which rows are mounted at click time), and why short conversations work.

**Second defect, same root cause.** Unmatched DOM rows are appended as *provisional*
questions — 43 listed where the index holds 40, duplicates changing as the user scrolls.
Pinned at exactly 3 by a `KNOWN DEFECT` assertion.

**No estimator change was made.** The owner's instruction was explicit: not before a real
failing log.

## Hypothesis tested and retired

The owner's stated first priority was realistic variable row heights, on the theory that
flat heights let any estimator hit on the first try. The mock's heights were rebuilt from
Probe A's empirical distribution — **25.7x spread, heavy-tailed, autocorrelated**, worst
6-row window at **0.15x the global mean**.

The jump still converged on the **first** interpolation:

```
i=1 targetRow=38 low=0@0 high=79@80060 est=38510 actual=38510 mounted=[35..40,79]
```

For heights drawn from a fixed distribution, the cumulative curve's *relative* deviation
from linear falls off as `1/sqrt(n)` — **more rows makes linear interpolation more
accurate**. Height variance cannot explain a failure that worsens with conversation
length. The harder distribution was kept; the hypothesis was not.

*(A detail in the owner's report had also moved: the mock had not used `ROW_HEIGHT = 260`
since the Phase 3 rebuild.)*

## Tier 3 — opus, mutation-driven

The lens verified by **injecting faults and running the suite**, not by reading. It also
went idle twice without delivering its report, which had to be recovered from its
transcript — the same "a wrapper signalled success, the work did not" pattern this
release keeps hitting.

### CRITICAL — the instrumentation would have broken the live run

The blind-probe trace block sat outside any try/catch. That callback runs from rAF or the
settle guard timer, outside any caller's try, and now performed geometry reads and
`JSON.stringify` **before** `attempt()`. A throw there skips `attempt()`, so `finish()`
never runs and `orbSetJumpBusyFor(token, false)` — reachable only through
`finish → safeDone` — never executes. Panel dimmed and click-blocked until reload.

**It could only fire when `trace.on` — i.e. exactly during the live debugging session the
instrumentation exists for.**

Proof: fault injected there → `busy=true stuck=true`, 19 s hang. Identical fault in the
interpolating branch, which sits inside an existing `try` → caught, `finish(…,'threw')`,
busy released. Same fault, opposite outcome; the asymmetry was the defect.

### Coverage regression introduced by the Windows fix

Moving the text lookup to backing data silently removed the only detection of *"correct
message resolved, viewport left elsewhere"*. `querySelector('[data-index=N]')` returned
null when the row was unmounted, so it doubled as a viewport assertion; `rowText(i)` reads
unconditionally and cannot. Proven: `scrollTop = 0` immediately after
`orbMarkJumpTarget` → **267/267 green**.

Restored as a **bounded-drift** check, not membership — membership is what raced on
Windows. Measured on the largest contiguous run, since the pinned tail drags `[0..5,79]`'s
centre from 2.5 to 39.5:

| Case | Drift |
|---|---|
| Correct jump | 0.5 – 2.5 |
| Windows' correct-but-later landing | 5.5 |
| Viewport left behind | **34.5** |
