## The two that matter most — both pre-existing, both on the ordinary load path

**Unbounded synchronous recursion on every index load.** `ciLoadIndex` invokes `done`
synchronously on its in-flight early return; `_ciConversationId` is assigned only on success
or degrade, so it stays null for the whole fetch window and `scanConversation`'s guard stays
true. Second scan → `ciLoadIndex` → `done(false)` → `scanConversation` → … → RangeError,
which escapes `scanConversation` so not even the DOM fallback runs.

**Success-driven refetch loop.** `_ciAssistantStale()` never clears a repeated signature, so
the resync fires, succeeds, sees the same mismatch, fires again — full payload every ~15.5s,
forever, on an idle page. Tool/artifact answers mismatch by construction. The exponential
backoff cannot help: it classifies failures, and this loop is all successes.

Both reproduced before fixing, per DEC-027:

| | old build `6bc7ed2` | fixed |
|---|---|---|
| latency 5ms → 1200ms | RangeError storm, 2 entries fail | 189/189 clean |
| tool-shaped row, 36s idle | 4 fetches (664, 1177, 16679, 32180ms) | 2 fetches, then silence |

## The finding behind the findings

**Nothing about the userscript changed between those failing and passing runs — only a
constant in the harness.** A 5ms fixture latency against a ~2.1s live payload, and fixture
API text that always equals the DOM, made both bugs unreachable in CI for an entire release
and through 23 rounds of independent review.

Recorded as **DEC-028: a fixture's defaults are part of the finding.** Both reproductions
are now permanent entries rather than scratchpad scripts.

## Honest limits of this round

- The test-integrity lens proved by mutation that `_sumBuildTimeline`,
  `_sumScrollToElement`, `_exportFromIndex` and `ciIndexStamp` can all be replaced with
  unconditional `throw` and the suite still passes — **no test opens the Summary or Tools
  panel at all.** The new guard entries cover the load path only. The summary/export surface
  remains unfixtured; it is v12.1 item 1's first target and is logged in HANDOFF §J.
- No test asserts that a jump to an already-mounted target moves the viewport.
- One NOTE left open deliberately: with a persistently *degraded* index, a summary click can
  still land on a recycled row (both stamps are null, so the guard compares equal, and
  `isConnected` does not catch recycled-but-connected). Narrow, requires a degraded session,
  and fixing it properly needs the item's text plumbed through four call sites.
