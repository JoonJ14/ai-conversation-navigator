## Tier 2 — deep logic

**Cross-path consistency (the highest-consequence check).** The mock DOM text and the API payload
text must be byte-identical or `ciMatchRowToPath` / `ciDeriveRowOffset` silently degrade. Two
separate implementations now exist (ES5 concatenation in the mock, template literals in the test
file). Both were extracted and **evaluated for all 40 turns**: identical on both the question and
answer sides, in both languages. Q1 = 95 chars, A1 = 82 chars — comfortably above the 60-char
matching floor.

**Boundary behaviour of the new length rule**, measured at the edges: 2-char ASCII dropped
(unchanged) · 1-syllable Hangul dropped · 2-syllable Hangul kept · mixed tokens (`api서버`) kept ·
empty string dropped · standalone Hangul jamo (`ㅋㅋㅋ`, `ㅠㅠ` — chat emoticons) stripped as noise ·
unassigned code points above the syllable block stripped.

**Regression surface outside the fingerprint.** The map fingerprint covers segmentation, labels
and topics. Global topics (`_sumExtractTopics`) and key-point dedup (`_sumDeduplicatePoints` via
`_sumWordOverlap`) sit outside it — they read the same token stream, so the construction argument
covers them, but this is recorded because the fingerprint alone does *not* prove it and saying so
would overstate the evidence.

What the delay actually cost is worth stating plainly: the lenses found **two CRITICALs that ten
Codex rounds did not**, and both were already merged into the PR branch by the time they arrived.

**They also worked from a stale diff.** The dump handed to them predated the ×/÷ carve-out; four
of the six noticed independently, re-read the working tree, and said so before reporting. Two
findings (the variant builder's `WIDE_STRIP`, the stale class in durable records) are consequences

### Finding — CRITICAL (fixed before PR)

**`×` and `÷` glue tokens.** `À-ɏ` reads as "Latin letters with diacritics" and very
nearly is — but `×` (MULTIPLICATION SIGN) and `÷` (DIVISION SIGN) sit inside it and are
the **only two non-letters in the block**. Written as one span they were kept, and because the old
ASCII-only class replaced them with a space, keeping them **glued tokens that used to split**:

| input | old | first v12.7 draft | shipped |
|---|---|---|---|
| `1920×1080 display` | `1920`, `1080`, `display` | **`1920×1080`**, `display` | `1920`, `1080`, `display` |
| `3×4 grid` | `grid` | **`3×4`**, `grid` | `grid` |

Found by asking what the range *contains* rather than what it is *named for*. Shipped class is
`[^a-z0-9À-ÖØ-öø-ɏ가-힣\s]`. Gated by `check-tokenizer.js`
**T9**, which asserts the **split** rather than the absence of the characters — a build that
dropped the whole run would also produce no `×` and would pass a weaker check.

### Claims, and how each was actually settled

| # | Claim | Method | Result |
|---|---|---|---|
| 1 | Pure-ASCII English tokenizes identically | **Brute force**: 20,000 random ASCII strings + 8 structured samples, old vs new; plus every ASCII code point checked for a `toLowerCase()` that escapes ASCII or changes length | 0 mismatches, 0 escapes |
| 2 | Removing the two length re-filters is a no-op for English | **Brute force**: 235,612 emitted tokens over 40,000 random ASCII/mixed strings, counting empty tokens and non-Hangul tokens < 3 chars | 0 and 0 — the guards were provably unreachable |
| 3 | `×`/`÷` were the only offenders and three sub-ranges fix it | **Exhaustive BMP enumeration against the shipped class** | 11,625 code points kept, **zero** non-letter/number/space; every seam correct |
| 4 | `HANGUL_RE` is safe shared at module scope | Flag inspection + scan of every module-scope regex for `.test()`/`.exec()` on a `/g` or `/y` pattern | No flags on `HANGUL_RE`; no stateful `.test`/`.exec` anywhere in the file |
| 5 | The new Korean fixture can genuinely fail | **Ran it against the pre-v12.7 build** | K1a `0 topics: []` RED, K1b `starts []` RED, K1c green (it gates Layer 4, not the tokenizer) — 2/31 red |
| 6 | `qPat`/`qAnyPat` did not weaken English assertions | Byte-compared all four generated patterns against `git show HEAD` | All four identical |

### Blast radius — clean, measured

- **No catastrophic backtracking.** Lazy fence pattern on 60,000 unterminated backticks: 2.0ms;
  linear across n = 1k/5k/20k/60k. Inline-code and URL patterns sub-millisecond.
- **The widened class is cheaper, not costlier, on adversarial input**: 64.5ms vs 96.4ms on
  200,000 characters (character classes are linear regardless of sub-range count).
- **Korean creates no new O(n²) term.** `_sumDeduplicatePoints` is fed by `KEY_POINT_PATTERNS`,
  which are English regexes — a Korean conversation matches none, so it does strictly *less* work.
- **Layer 3 clean.** No page global, no `unsafeWindow`, no `fetch`/`history` patching. Every
  caller passes a string (`_sumBuildTimeline` guards each `text` with `|| ''`).

### Cost, and a measurement that reversed itself

Tokenize call counts and characters are **identical to baseline** at every config (902x/2.8M,
1065x/2.6M, 908x/7.6M, 1136x/6.6M). The added per-token predicate costs **+7.4%** of the tokenize
term (40.9ms → 43.9ms per 1.53MB, medians of 12 interleaved runs) ≈ +20ms against a ~1.2s live
generate.

**The first run of that benchmark reported the new tokenizer 68% FASTER** — impossible for
strictly added work. Cause: old benched first, new second, so V8 had JIT-warmed the shared path.
Warming both and interleaving A/B/B/A gave the real number. *A microbenchmark that runs A then B
measures the order as much as the code.* Wall-clock map times were **not** used for this
conclusion — the machine was running a two-engine Playwright suite concurrently, and timing under
contention is not a measurement.

## GitHub Codex loop

### Round 1 — 2 findings, both P2, **both real, both fixed**

**1. Normalize canonically equivalent text before filtering.** Neither the DOM nor the API
guarantees a normalization form, and **macOS produces NFD for Korean input** — precisely the
platform the one Korean-speaking user this translation exists for may be typing on. Measured
against the shipped class:

| input | NFC | NFD |
|---|---|---|
| `인증 토큰이 만료되어 세션이` | 4 tokens | **0 tokens** |
| `café naïve résumé était` | `café naïve résumé était` | **`cafe nai sume tait`** |

So the fix was defeated in NFD exactly the way the ASCII-only class was, and accented Latin was
not merely dropped but **corrupted** — `résumé` → `sume`. Codex's cited examples were exact.
Fixed with `.normalize('NFC')` as the tokenizer's first step (an ES2015 built-in, like the `Set`
this file already uses; the ES5 constraint is on syntax). Cost: 4.4ms per 0.5MB on already-NFC
text. Gated by **T10** (NFD Korean must tokenize *identically to NFC*, not merely non-empty) and
**T11** (NFD accented English must not become other words) — both assert equality with the NFC
result, because the Latin failure mode was corruption and a non-empty check would have passed it.

**2. The variant sweep did not measure the shipped pipeline.** The builder patched only
`_sumTokenize`, leaving the pre-v12.7 `< 3` and `> 2` guards in `_sumExtractTopicsFromText` and
`_sumExtractTopics` — and the map harness reads those topic lists for labelling and for the
merge's `_sumTopicOverlap`. Fixed, and **the whole sweep re-run**. Two rows moved:
particle-normalization improved. **Read at the time as "the ranking held" — that reading did not
survive round 3**, which found a third defect in the same comparison and reversed it outright.
The finding was material in the direction that mattered: it improved the *rejected* option.

### Round 2 — 1 finding, real, fixed

`probes/README.md` Path D said "from an EXPLICIT pre-change ref" and then ran
`git show origin/main:...` — the pre-change build only while the candidate is unmerged. After
merge, `origin/main` IS the candidate, so the gate compares the build with itself and is
guaranteed green. Path C above already documents that exact trap; Path D reintroduced it by
copying the command without its caveat.

### Round 3 — 2 findings, real, and one of them **overturned a conclusion**

**1. The payload's ground truth was language-dependent — the most consequential finding of the
whole arc.** Topic-block lengths were drawn from the same LCG as the text, and `koSentence`
consumes extra draws, so Korean was scored against **9 boundaries in different places** where
English had 8:

```
en  29,57,87,119,159,199,239,279          (8)
ko  29,57,83,117,157,187,217,251,287      (9)
```

Every cross-language claim was meaningless, and the *variant ranking* had been computed against
it. Fixed by deriving the schedule from a throwaway English render in every language, which
leaves the English payload **byte-identical** (verified at all four knob settings) and is
guarded at require time by `assertEnglishScheduleUnchanged()`.

**Re-run, the ranking reversed:** particle normalization leads on recall, 31/32 vs 28/32. The
rejection recorded earlier in this document is **retracted**. v2 still ships, on grounds that do
not depend on the score (same segment-count regime as English; no hand-maintained word list),
and the live check is the arbiter.

**2. `merge-base` is also self-comparing after merge.** The round-2 fix swapped `origin/main`
for `$(git merge-base HEAD origin/main)`, but on a checkout where HEAD and origin/main name the
merged revision that returns HEAD. Both Path C and Path D now use a pinned sha with a
confirm-the-ref diff.

**Provenance split — the DEC-029 stop signal.** Roughly 4 findings were on code as originally
written (NFC, variant downstream, T5 completeness, README claim); roughly 9 were defects in
*fixes made during the cycle* (the merge-base fix that was still self-comparing, the KP_RATE
exemption I omitted, the stale numbers my own corrections left behind in four files, the NFC
step my own variant fix omitted). That ratio crossed parity by round 5 and stayed there — and
the loop kept finding real defects anyway, which is the honest reason to stop on a CLEAN round
rather than on the ratio.

**The single most valuable finding was round 3**, which invalidated the comparison this PR's
headline conclusion rested on and forced a retraction. No amount of local review had caught it:
Tier 1–3 all checked whether the *code* did what it claimed, and the defect was in the
*yardstick*.

**All ten rounds share one shape:** the thing measured was not the thing shipped — once in the
input's encoding, once in the build under test, once in the yardstick itself. That is a better
description of this arc's failure mode than "one configuration is not a measurement", which was
only the first of the three.

## Not fixed here, on the record

- **Key points remain unavailable in Korean** — `KEY_POINT_PATTERNS` is a set of English regexes;
  no tokenizer change reaches it. ROADMAP 0a.
- **Korean sub-segment labels carry particles** (`세션이` rather than `세션`). A display-only
  normalizer would fix the reading without touching any measure; deliberately not bundled, and
  §G.1 of the handoff makes it a question for the live check.
- **Particle normalization's rejection did NOT survive the Codex loop.** The comparison behind
  it was invalid (Korean was scored against a different ground truth than English). Re-run on a
  language-independent schedule it leads on recall, 31/32 vs 28/32. v2 ships on grounds
  independent of the score — same segment-count regime as English, no hand-maintained word
  list — and the live check decides (DEC-031, DEC-041).
