## Self-review before the loop — what the claim rests on

The output-identity argument has three legs, each checked against the code rather than
assumed: (1) `_sumBuildSubSegments` is pure in its `messages` argument — it reads `m.text`
and `m.globalIdx` and calls only pure helpers; (2) no merge decision reads `children` —
`grep` for `.children` finds exactly two consumers, the renderer and the new attach function;
(3) `messages` arrays are never mutated after a segment is built — every merge allocates a
fresh `concat`, and the commit path re-binds `currentMsgs` rather than mutating it.

Empirical backstop, because an argument is not a measurement: structural fingerprints
(labels, spans, topics, entity counts, message membership, and each child's own membership)
over 32 config/engine combinations, identical before and after.

## GitHub Codex rounds — 6 findings, 1 false positive, all in this arc's tooling

Zero findings in the shipped userscript across every round, matching the v12.4/v12.3 pattern
(a change small enough to argue about line-by-line draws review pressure onto its harness).

**Round 1 (`b1bad36`) — 2 × P2, both real, both "a gate that cannot fail":**
1. A requested configuration missing from the baseline was logged and then counted clean, so
   a narrower baseline let `--baseline` exit 0 having compared nothing for it.
2. When nothing merges, `initial === final` and the eager/deferred formulas coincide; the
   eager test ran first, so a v12.5 build printed as `eager` at every short config.

**Round 2 (`344879a`) — 1 × P2, real:** the between-repeats determinism check incremented a
counter whose only `process.exit(1)` lived inside the `--baseline` block. A `--save` run —
the documented way to *make* a baseline — could watch one build produce two different maps,
log it, write the first as the reference, and exit 0. Fixed by separating the two failure
classes (`repeatMismatches` vs `baselineMismatches`), failing on either, and refusing to
write a `--save` file from a run that disagreed with itself.

**Round 3 (`41e70d6`) — 1 × P2 real, 1 false positive:**
- Real: a sweep *narrower* than the baseline still printed "every fingerprint identical to
  baseline". The verdict now names its scope (`N/M baseline configurations exercised`), lists
  what was not run, and fails on missing coverage; `--partial` keeps single-config iteration
  possible while saying so in the verdict.
- **False positive:** round 2's exit-path finding re-reported against the line the block had
  moved to. Verified at the head rather than dismissed — the exit is outside the `--baseline`
  block and covers both counters, and the sabotage run in the previous commit demonstrated
  `exit 1`.

**Round 4 (`bd03e97`) — 2 × P2, both real, and the sharper pair:**
1. **The fingerprint did not cover child membership.** It recorded each child's label, span and
   message COUNT, but the renderer hands `child.messages` to `_sumFirstJumpable`, so a change
   preserving label+span+count while altering or reordering membership would send a
   sub-segment click to a different row — and the gate would have called it identical. The
   serializer now records each child's `globalIdx` sequence, exactly as the parent segment
   does. **This voided the baseline** (the format changed), so it was regenerated from the
   pre-change build and the full matrix re-run: **32/32 identical under the stricter
   fingerprint**. The equivalence claim in every doc was rewritten to say what is actually
   compared.
2. **The documented baseline recipe could compare a build with itself.** It said
   `git show HEAD:…`; once the candidate is committed, `HEAD` *is* the candidate, so the
   "baseline" and the candidate are the same bytes and the gate is guaranteed green. My own
   runs were not affected — the extraction happened while `HEAD` was still the pre-fix
   tooling commit, verified after the fact by diffing the extracted file against
   `origin/main` — but the recipe was a trap for the next reader. It now names an explicit
   pre-change ref and tells you to diff the extracted build before trusting a green.

Every fix in this loop was demonstrated able to FAIL before being trusted: a deliberately
truncated baseline (exit 1 with the key missing, 0 with it present), a temporary fingerprint
sabotage on repeat 2 (file refused, exit 1), and a narrow sweep with and without `--partial`
(exit 1 / exit 0). Full matrix re-run clean after each round.

**Provenance (DEC-029):** by round 3 the findings were against code the loop itself had
written one round earlier, all P2, all in measurement tooling, with the shipped change
untouched throughout — the documented stop signal. Round 4 is the honest exception to
stopping there: both findings were about what the equivalence gate *proves*, and one of them
showed the gate had been passing on an incomplete comparison. A loop-era finding that
weakens the evidence for the shipped change is worth another round; a loop-era finding about
log wording is not.
